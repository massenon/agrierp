# 28 — MODULE RAPPORTS, EXPORTS (PDF, xlsx) ET IMPORTATION EN MASSE

## USAGE

- **Quand l'utiliser** : (a) rapports/PDF/xlsx : au jalon W6f, APRÈS la comptabilité (`26_`) car le résultat net doit venir d'UNE source ; (b) importation en masse : au jalon W7a, dès que Stocks et Ventes existent (« stocks d'abord », client : « très important »). Fournir des états lisibles et exportables, tous cohérents avec la comptabilité (mêmes chiffres), via UN générateur PDF et UN exporteur xlsx ; et permettre l'initialisation et l'alimentation en masse par tableur sans ouvrir de second chemin d'écriture.

## 3. Rapports & Exports — structure commune aux 6 onglets

Ordre : (1) bouton « Exporter PDF » (haut-droite, hors du panneau d'onglet, visible en permanence : exporte l'onglet ACTIF) ; (2) panneau KPI (accordéon mobile) ; (3) visualisation éventuelle ; (4) filtres + « Réinitialiser » ; (5) tableau. Un seul générateur : `generateOfficialPDF()` du prototype → `EtatPdfGenerator` unique (en-tête entreprise, tableau, pied de page ; réutilise la structure de la facture : E9, J2 §3) ; **pas une implémentation par onglet**. Les états sont générés À LA DEMANDE (aucune génération planifiée, B1 §6). Filtres communs : plage de dates (obligatoire pour tout état transactionnel), filière, exercice (états financiers, lecture seule d'un exercice clos).

**Règles** : seules les classes 6 et 7 comptent dans recettes/dépenses (les contreparties 531, 512, 411, 401 doubleraient les totaux) ; Résultat net de l'onglet 1 = celui de la Comptabilité (test d'égalité stricte entre les deux ViewModels : RM-CPT-04) ; trésorerie = 531 + 512 (Q-PIL-1 pour le KPI du tableau de bord) ; **échéance = échéance réelle en base** (statut « Sans échéance » si absente : RM-VTE-04), jamais la date de vente ; le rapport de stocks valorise les produits finis au COÛT de revient (« Non valorisé » + mention « Hors N article(s) sans coût de revient renseigné » ; la colonne « CMUP » du prototype affichait le prix de vente : corrigé) et les intrants au PMP ; valeurs de référence du prototype (142 000 F, 312 000 F, 184 sujets, 84 %) = constantes de maquette, JAMAIS des données ; période par défaut = mois en cours de l'exercice affiché (RM-CPT-07).
**États opérationnels (J2 §2)** : Récapitulatif Mensuel par Espèce (mouvements du mois, effectif début/fin, taux de mortalité : RM-ELV-08) ; Bilan Technico-Économique (coût de production vs revenus par filière : dépend de l'analytique, Q-CPT-5) ; État des Stocks ; Historique des Ventes (période libre) ; Analyse Clients/Créances. États financiers réglementaires : `26_` §6. **Lettre de relance** : titre « Lettre de Relance » avec échéance dépassée ; « Rappel de Solde » sans échéance (« présente un solde restant à régler »).
**Hors ligne au poste** : calcul LOCAL sur la base du poste (lecture) ; l'état affiche l'heure de la dernière synchronisation (« Données au JJ/MM à HH:MM ») ; pas de génération serveur hors ligne.
**États vides** : « Aucune donnée sur la période. » ; KPI sans source : « — ».

## 4. Exports

- **PDF** : un seul `EtatPdfGenerator` (entreprise, logo/favicon si configurés, tableau, pied) ; portrait par défaut, **paysage pour l'inventaire** (avec base de valorisation et réserves en toutes lettres) ; QR et mentions MeCeF sur la facture (`24_`). Données utilisateur insérées dans le PDF échappées (pas d'injection de structure). Nom de fichier : `<Etat>_<AAAA-MM-JJ>.pdf`. Impression : pilote système ; repli = export fichier (B3 §6).
- **xlsx** : un seul exporteur (`ExportTableur.construire(DocumentOfficiel)` côté poste, paquet `excel` ; au web AgriERP produit un CSV sous le libellé « Excel » : à LogiALVIA, produire un VRAI xlsx via `phpoffice/phpspreadsheet`/`maatwebsite/excel` — Q-IMP-2) ; cellules = valeurs typées (nombres en nombres, dates en dates) ou texte tel qu'affiché (à décider : le poste d'AgriERP exporte le texte affiché) ; nom d'onglet ≤ 31 caractères ; permission `export-<module>`.
- **« Exporter une table »** (Paramètres > Sauvegardes) : export brut d'une table, réservé à `admin`, jamais le jeton e-MECeF ni les secrets (SR-040).

## 5. Importation en masse par xlsx — À CONCEVOIR (priorité haute du client)

**Rappel** : fonction INEXISTANTE ailleurs (guide bloc 21 : seuls existent l'import CSV d'un relevé bancaire, l'import d'un module depuis une sauvegarde SQL, l'import du plan SYSCOHADA). Tout ce qui suit est une PROPOSITION à valider (Q-IMP-1) ; rien n'est construit.

**Principes** : (1) un import n'ajoute AUCUNE règle : chaque ligne passe par le point de passage unique de l'écran et de la synchronisation (`ProductCatalogService::creer` → `AdjustStockAction` « Stock initial », `CustomerCatalogService`, `SupplierCatalogService`, `PlanComptableService`, `SaisieBandeAction`…) ; les refus de l'import sont les refus de ces services, mot pour mot ; (2) web d'abord (doctrine art. 5), puis poste fidèle ; (3) création SEULE, jamais d'écrasement (mise à jour en masse = phase ultérieure) ; (4) idempotence ; (5) ligne par ligne, une transaction par ligne.

**Écran « Importation en masse »** — 5 étapes dans UNE page : (1) **Choisir le module** (cartes : Produits vendables et stock initial, Intrants et stock initial, Clients, Fournisseurs, Plan comptable (comptes complémentaires), Barème de rationnement ; Bandes en phase 3) — modules non autorisés absents ET refusés au serveur ; (2) **Télécharger le modèle .xlsx** (bouton « Télécharger le modèle ») ; (3) **Déposer le fichier** (extension `xlsx`, taille, lisibilité, modèle et version reconnus : « Ce fichier n'est pas le modèle « Clients » (version 1) : téléchargez le modèle à jour. ») ; (4) **Aperçu avec validation ligne par ligne** (25 lignes par page ; état Valide · Ignorée (déjà présente) · Refusée + motif ; compteurs « N lignes lues · N valides · N ignorées · N refusées » ; filtre « Refusées seulement » ; AUCUNE écriture ; contrôle préalable de l'exercice) ; (5) **Confirmer** « Importer N lignes » (désactivé à 0) → rapport téléchargeable (xlsx : une ligne par ligne du fichier avec résultat et motif). Hors ligne : écriture locale puis `pending` ; le rapport dit « créée sur ce poste, à synchroniser ».
**Modèle versionné** (`Modele_<Module>_v1.xlsx`) : feuilles « Instructions » (nom, version, rôle des colonnes, formats, exemples, limites), « Données » (en-têtes figés, obligatoires marqués `*`, VIDE), « Listes » (listes déroulantes de validation), métadonnées (modèle, version, empreinte SHA-256 vérifiée par test). Formats : montants FCFA ENTIERS (« Montant invalide à la ligne N : un nombre entier de FCFA est attendu. ») ; quantités décimales (virgule ou point) ; dates `JJ/MM/AAAA` ; téléphone en texte (zéro initial conservé). Taille maximale proposée 5 000 lignes / 5 Mo (Q-IMP-3).
**Modules et colonnes — à décliner pour logialvia depuis ses PROPRES tables** (le guide en donne les colonnes d'AgriERP, qui n'a qu'une table `products` ; logialvia a DEUX familles : intrants et produits vendables, donc deux feuilles/modèles — Q-IMP-4) : Produits vendables : Désignation* · Catégorie* (Avicole / Commerce Annexe / Cuniculture / Pisciculture) · Unité* · Tarif indicatif* · Tarif haut · Seuil d'alerte · Stock initial* · Coût de revient · Catégorie d'effectif · Filière ; Intrants : Désignation* · Catégorie* (Intrants Provende / Marchandises / Vétérinaire) · Unité · Quantité · Seuil · PMP ; Clients : Nom complet* · Téléphone · Date de naissance ; Fournisseurs : Nom* · Téléphone · Adresse · Fournit ; Plan comptable : N° compte* (unique) · Intitulé* · Classe* · Sens ; Barème : Filière* · Stade* (libellé EXACT) · Ration g/j*. **Exclus de la v1** : utilisateurs (mots de passe dans un tableur), historique de fiches/ventes/écritures (faits datés soumis à cascade, stock et comptabilité : un chemin parallèle).
**Idempotence (3 filets)** : fusion serveur par clé naturelle (`FusionReferentielsService`) ; UUID v5 déterministe dérivé de `module + clé de ligne normalisée` ; journal d'import (empreinte SHA-256 du fichier : « Ce fichier a déjà été importé le … par … », avertissement non bloquant). Doublon interne : « Ligne N : doublon de la ligne M ». Un produit déjà présent est IGNORÉ et son stock initial N'EST PAS ajouté (deux déclarations d'un même article = le même stock physique).
**Transport poste → serveur** : par la synchronisation ordinaire (faits `pending` à UUID), PAS par un endpoint d'import dédié (hors ligne, idempotence et droits existants, aucune seconde porte d'écriture). **Droits** : `manage-<module>` ; audit : une ligne `import.masse` par fichier (module, version, compteurs, jamais le contenu) ; journal d'import (UUID, module, version, nom, empreinte, auteur, date heure du Bénin, compteurs).
**Pièges** : un import qui exécute du SQL ; un stock initial écrit dans `stock_qty` sans mouvement ; `create(['id'=>…])` ignoré en silence (poser l'`id` hors de `create()`) ; un zéro de téléphone perdu ; nom d'onglet > 31 caractères ; en-tête renommé ; confondre « ignorée » (déjà là) et « refusée » (erreur).
**Dépendances** : logialvia n'a NI `excel`, NI `file_picker`, NI `uuid` dans `logialvia_app/pubspec.yaml` (à ajouter) ; le serveur ajoute `maatwebsite/excel` au `composer.json` (le doublon de clé d'AgriERP est à ne pas recopier). **À DÉFINIR** : Q-IMP-1 modules et ordre, d'où viennent les données (cahiers ? Excel existants ?), date d'ouverture du stock initial ; Q-IMP-2 vrai xlsx au web ; Q-IMP-3 taille maximale ; Q-IMP-4 deux familles de stock ; Q-IMP-5 « tout ou rien » en option ou ligne par ligne seul ; Q-IMP-6 qui a le droit d'importer, conservation du rapport.

## 6. Critères d'acceptation

- [ ] Résultat net de l'onglet « Recettes et Dépenses » = Résultat net de l'écran de comptabilité (égalité stricte, test).
- [ ] Un KPI de stock non valorisé affiche « Hors N article(s)… » ; le total ne prend jamais un prix de vente pour un coût.
- [ ] Créance sans échéance : statut « Sans échéance », jamais « En retard » ; PDF « Rappel de Solde ».
- [ ] « Exporter PDF » exporte l'onglet actif, via UN générateur.
- [ ] (Import, si construit) ré-import du même fichier : 0 création, N ignorées, avertissement « déjà importé » ; ligne erronée refusée avec le motif du service, les autres entrent ; stock initial = mouvement « Stock initial » ; fichier d'une autre version refusé ; aucun `INSERT` direct hors services (garde de lecture de sources).
