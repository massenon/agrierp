## 3. Les 7 onglets de Paramètres Généraux (libellés exacts)

### Onglet 1 — « Modules Actifs » (BR-ADM-002, I2, F8)
Texte d'introduction : « Goliaths et Pintades sont l'activité principale confirmée d'ALLMANY et restent toujours actifs. Les filières ci-dessous sont désactivées par défaut — activez-les uniquement si l'activité démarre réellement. » 5 lignes à bascule (`toggle-switch`) : Goliaths (toujours actif, `checked disabled`) · Pintades (idem) · Poissons-Chats / Pisciculture `pisciculture` (« fiche construite, paramètres non confirmés », désactivé par défaut) · Poulets / Pondeuses `aviculture_classique` (« Filière dupliquée — désactivée par défaut ») · Lapins / Cuniculture `cuniculture` (« Copie fidèle — désactivée par défaut »). Ajouts de logialvia : module `mecef` (activable seulement avec IFU **et** RCCM : BR-ADM-004), mode « Données de Test » (faux par défaut, posé ICI et non dans l'onglet qu'il protège), assistant de démarrage/aide (`assistant_demarrage`, éteint par défaut : guide bloc 13f). Après activation : « Activer un module affiche immédiatement sa fiche et son raccourci dans le menu latéral et le panneau d'accès rapide. »
**Effet** : menu et dashboard (aperçus) mis à jour immédiatement ; URL directe refusée (redirection) ; données historiques intactes ; KPI consolidés excluent les filières inactives mais les rapports historiques incluent les périodes d'activité ; réactivation = reprise de la cascade. Goliaths et Pintades n'ont PAS d'entrée `MODULES_ACTIFS` ; `estActif('goliaths'|'pintades')` vaut toujours vrai ; `basculer` est un no-op. Droit `manage-modules` (admin seul).

### Onglet 2 — « Données de l'Entreprise »
**Informations Générales** : RAISON SOCIALE * · NOM DU PROMOTEUR · ADRESSE DU SIÈGE D'EXPLOITATION · TÉLÉPHONE PRINCIPAL · EMAIL DE CONTACT (format e-mail). **Informations Légales & Fiscales** : IDENTIFIANT FISCAL UNIQUE (IFU) * (chiffres uniquement ; 13 chiffres exigés par la facture normalisée) · REGISTRE DU COMMERCE (RCCM) (facultatif ; requis pour activer MeCeF). **Conditions de vente** : DÉLAI DE PAIEMENT PAR DÉFAUT (JOURS) (vide tant que le client ne l'a pas communiqué ; ≤ 0 = non fixé : Q-VTE-1). **Configuration Email (SMTP)** : SERVEUR SMTP · PORT · SÉCURITÉ (TLS / SSL / Aucun) ; mot de passe SMTP chiffré, jamais journalisé ni servi au poste ; bouton « Tester la configuration » (envoi réel d'un message d'essai, résultat en français). **Logo / Favicon** : deux zones de dépôt ; validation stricte (signature réelle `png/jpg/jpeg/ico`, ≤ 2 Mo, nom regénéré en UUID : SR-045) ; consommés par le PDF (E9) et l'onglet du navigateur ; au web : OUI ; au poste : tiré du serveur (le poste d'aujourd'hui ne les reprend pas : écart assumé de F8). **TVA** (PROPOSÉ, Q-TVA-1) : case « Assujetti à la TVA » (RM-TVA-01). **Facturation normalisée (e-MECeF)** (onglet/section dédié au web : voir `42_`) : mode (désactivé / e-MECeF / boîtier), adresse du service (préréglages essai et production), opérateur, **jeton** (secret chiffré, masqué « •••• », « Remplacer », « Effacer », JAMAIS servi au poste), « Tester la configuration » (UN `GET /info/status`, jamais `POST /invoice`) ; au poste d'aujourd'hui le jeton est saisi (« Enregistrer le jeton », coffre `flutter_secure_storage`) : **à retirer à la bascule** (D-SRV-6). Bouton « Enregistrer les Modifications » (pleine largeur en mobile). Un seul point de passage `EntrepriseService`/`MecefReglageService` ; une seule colonne IFU.

### Onglet 3 — « Gestion Utilisateurs » (BR-ADM-003, guide bloc 2)
Tableau : Nom · Identifiant · Rôle (libellés « Administrateur », « Comptable », « Agent de Vente », « Agent d'Élevage » : 4 rôles, TRANCHÉ DV-07) · Statut (Actif / Archivé) · Actions. Bouton « Ajouter un Utilisateur » → modale : NOM COMPLET *, IDENTIFIANT * (SANS arobase, unique ; le prototype n'avait que Nom + Rôle : un compte sans identifiant ni mot de passe ne pourrait pas se connecter), RÔLE * (Comptable / Agent de Vente / Agent d'Élevage ; **`admin` n'est jamais créable** : seul le compte initial), MOT DE PASSE * (politique : 8 caractères, 1 majuscule, 1 chiffre ; Q-ADM-1) + confirmation. **Modifier** (mot de passe facultatif : absent = conservé ; jamais journalisé ni servi), **Archiver / Réactiver** (suppression LOGIQUE seulement ; logialvia supprime physiquement : à remplacer ; refus : son propre compte, un compte archivé ne se modifie pas ; le DERNIER admin ne peut s'archiver ; un compte archivé ne se connecte plus et ses sessions/jetons se ferment), **Réinitialiser le mot de passe** (icône ; mot de passe TEMPORAIRE soumis à la politique, `must_change_password`, sessions et jetons détruits, audit `user.password_reset`, jamais le mot de passe dans l'audit ; refus pour son propre compte et un compte archivé). **Code de secours** du dernier administrateur : 24 caractères, affiché UNE fois, seule l'empreinte SHA-256 stockée, un seul code actif, usage unique, 5 échecs = blocage 15 min, nouveau code après usage ; procédure imprimable (`docs/CODE_SECOURS_ADMIN.md`) ; script de secours côté poste : `logialvia_app/outils/reinitialiser_mot_de_passe_admin.dart`. Restaurer un utilisateur depuis la corbeille : admin seul.

### Onglet 4 — « Modes de Paiement »
Texte : « Conformément au CDCT, seuls 2 modes de règlement sont retenus — pas de virement bancaire ni de multi-comptes. » Deux tables : « MODES DE RÈGLEMENT » (Espèces, Mobile Money : toujours actifs, non désactivables) et « CONDITIONS DE PAIEMENT » (Comptant, Avance : l'avance est une CONDITION appliquée à une vente Espèces/Mobile Money, pas un canal ; divergence tranchée par la Gérante ; migration v15 pour les ventes antérieures ; garde au POS : le choix d'une condition est exigé). Mobile Money = information de traçabilité, pas transaction bancaire (BR-028). Q-PAY-1 : un 3e mode (virement, chèque) est-il à prévoir ?

### Onglet 5 — « Sauvegardes » (guide F8 ; SR-051)
Boutons : « Générer une sauvegarde » · « Exporter une table » (admin, jamais les secrets) · « Ouvrir le dossier » · « Copier le chemin » (poste) ; liste des sauvegardes (nom, date, taille) avec exporter/supprimer/**restaurer**. **Restauration** : le fichier choisi est MIS EN ATTENTE dans le dossier applicatif et appliqué au PROCHAIN démarrage avant l'ouverture de la base ; quatre contrôles avant le moindre octet (signature SQLite des 16 premiers octets ; `PRAGMA integrity_check` ; tables `utilisateurs`, `roles`, `parametres_entreprise` présentes ; `user_version` ≤ version du logiciel ; une base plus ancienne est acceptée et migrée) ; fichier ouvert en lecture seule pour ces contrôles ; la base précédente est conservée dans le dossier des sauvegardes ; annulable tant qu'on n'a pas redémarré. **Au web** : sauvegarde quotidienne 02:00, rappel hebdomadaire (lundi 08:00) de télécharger la sauvegarde adressé au rôle `admin` ; rétention À DÉFINIR (AgriERP : 30 jours puis dossier vidé ; pas d'archive figée à la clôture : Q-SAV-1/Q-CPT-8) ; le jeton e-MECeF y est chiffré par `APP_KEY`. Une sauvegarde automatique est faite AVANT toute migration de schéma (refus de migrer si elle échoue). `exporterSauvegarde()` : validation du fichier (I3 §2).

### Onglet 6 — « Corbeille » (F8, v22)
« Supprimer » n'efface plus rien : **7 suppressions** passent par la corbeille (copie JSON complète dans `CORBEILLE`, liste blanche stricte de types `TypeArchivable` pour le nom de table) : produits du catalogue, intrants, barèmes de rationnement, échéances de prophylaxie, lots d'incubation, utilisateurs, messages à l'éditeur. **Les écritures comptables n'y entrent JAMAIS** (TRANCHÉ DV-05 : intangibilité OHADA ; une écriture ne se supprime pas et ne se restaure pas, elle se contre-passe : `26_` §4, `15_` RM-CPT-09 ; logialvia retire `supprimerPiece` et le type `Ecriture` de la liste blanche `TypeArchivable`). Colonne « Archivé par » (auteur transmis de l'écran au dépôt ; `null` légitime hors session, jamais « admin » inventé). Règles : **archiver** = qui gère l'écran ; **restaurer** produit/intrant/barème/échéance/lot/message = tout le monde (ayant accès à l'écran) ; **restaurer un utilisateur = admin seul** ; **supprimer définitivement / vider la corbeille = admin seul**, modale d'avertissement propre renvoyant vers « Sauvegardes » ; restauration refusée si la référence est réoccupée ou si l'élément est déjà sorti. **Contradiction avec AgriERP : TRANCHÉE (DV-05, Q-CPT-3 fermée)** : AgriERP avait raison, les écritures sont exclues de la corbeille (sinon le Bilan ne s'équilibre plus). Migration : toute écriture déjà présente dans une corbeille existante du poste est restituée au journal (hors périmètre de ce registre). Au web : chaque chemin d'archivage écrit un audit avec `entity_type/entity_id` (clé « Archivé par »).

### Onglet 7 — « Données de Test » (F8, v23)
Remet à zéro l'ACTIVITÉ, jamais l'exploitation. **Effacé** : ventes, lignes, devis, clients, achats, lignes d'achat, mouvements d'intrant, écritures, notes annexes, clôtures, fiches journalières, fiches de ventes, lots d'incubation, machines, soins, infirmerie, corbeille. **Préservé** : comptes, rôles, permissions, paramètres d'entreprise, plan comptable, exercices, modules actifs, préférences du poste, journaux d'audit (« une opération qui efface l'activité ET la trace de qui l'a effacée n'est pas une réinitialisation »). **Double verrou** : mode « Données de Test » activé (Modules Actifs, faux par défaut y compris après migration) ET rôle admin. Boutons « Peupler un mois de démonstration », « Réinitialiser les données » : modale d'avertissement avec le NOMBRE RÉEL de lignes par table (`apercu()`, ne touche à rien), la liste de ce qui est conservé, le rappel que la sauvegarde est le seul retour en arrière (la réinitialisation ne passe pas par la corbeille) ; une seule transaction ; seeders rejoués pour garder un exercice ouvert. Au web : trois verrous et marque `data_reset_at` (409 aux envois portant une marque inconnue : SR-026).

### 4b. Formulaire « Incubation et règles » (`/parametres/elevage`, 5ᵉ onglet ; TRANCHÉ DV-11)

Écran du web d'abord (puis du poste, fidèle à 100 %). Il édite les règles d'incubation **par espèce** ; la description complète (mêmes champs, mêmes messages) est dans `23_MODULE_ELEVAGE_PAR_FILIERE.md` §6b, qui est le texte de référence.

Les pastilles d'espèce sont celles de la couveuse **d'après le code de LogiALVIA** (`cycle_incubation.dart`, enum `EspeceCouvable`) : **Pintade** (28 j) et **Goliath** (21 j). Aucune « poule » n'est une espèce de couveuse dans LogiALVIA ; la poule n'apparaît que comme **mère porteuse** du mode « couvaison naturelle » (champ 4). Une autre volaille se rajoutera comme nouvelle ligne d'espèce, sans changer le formulaire. Chaque espèce a son propre formulaire (une ligne `incubation_rules` par espèce).

**Boutons** : « Enregistrer les règles de l'espèce » (primaire) ; « Rétablir les valeurs recommandées » (secondaire, avec confirmation ; rien n'est enregistré avant « Enregistrer »). **Toast de succès** : « Règles d'incubation enregistrées. » ; **toast d'échec** : « Enregistrement refusé : corrigez les champs en rouge. »

**Règles communes** : édition réservée à `manage-elevage` (administrateur et animalier ; à la différence des seuils de ferme de provende, réservés à l'administrateur) : `authorize('manage-elevage')` en première ligne de la méthode d'écriture, serveur ET écran ; toutes les validations en français avec noms d'attributs français ; **audit** `incubation_rules.updated` (utilisateur, espèce, anciennes et nouvelles valeurs) ; une modification **ne change jamais un cycle déjà créé** (le cycle garde son instantané `duree_incubation_jours`, `fenetre_*`, `mode_incubation`, `transfert_eclosoir_jour`) : elle ne vaut que pour les cycles créés ensuite. Les repères d'incubateur (champs 10 à 13) et de conservation (8, 9) ne produisent que des **avertissements**, jamais un blocage. Aucune valeur de ce tableau n'est une constante du code : ce sont les VALEURS PAR DÉFAUT du semis ; elles sont « repères terrain, à valider par le technicien ».

**Construction équivalente (web d'abord, puis poste).** Modèle repéré dans AgriERP : `app/Livewire/Elevage/ParametresElevage.php` édite des paramètres élevage par des méthodes `save…()` qui font `$this->authorize('manage-elevage')`, `$this->validate([...], [], [attributs français])`, écrivent la ligne (`ElevageNumberingSetting::current()->update(...)`, `CompanySetting::current()->update(['rappel_soins_jours' => ...])`), `AuditLog::record('elevage_numbering.updated', 'elevage')` puis un toast. Côté poste, `lib/features/elevage/parametres_elevage_repository.dart` fait la même écriture en local (`enregistrerNumerotation`, `enregistrerRappelSoins` : insertion avec `DoUpdate`, `syncStatus: pending`, `updatedAt`) et la ligne part à la synchronisation ; le serveur revalide et peut refuser (`conflict` avec motif). **AgriERP n'a pas de module d'incubation de pintades** : aucune table ni écran à copier ; seuls ce motif d'édition et ces deux paramètres existants servent de référence. Ses durées de cycle de reproduction (lapins/porcs : palpation à +14 j, sevrage à +42 j dans `SuiviReproduction.php`) sont aujourd'hui des valeurs du code, non éditables : elles sont citées **en référence** (même famille de règle « durée de cycle »), pas comme exemple de formulaire déjà éditable.

## 5. Hors ligne et synchronisation

Paramètres Généraux est un écran du WEB : au poste, lecture (tirée) + gestes locaux (sauvegarde locale, corbeille locale, données de test locales, `PREFERENCES_POSTE`). Toute modification de référentiel d'administration (entreprise, utilisateurs, rôles, modes de paiement) faite depuis le poste, si elle est permise, part comme DEMANDE (`settings_requests` : kinds `entreprise`, `mode_paiement`, `role`…) contrôlée par droit au serveur (modèle `SyncController::pushSettingsRequests`) ; l'état redescend au tirage. `utilisateurs`, `roles`, `permissions_role`, `audit_logs`, `security_logs` : serveur seules ; `parametres_entreprise` : synchronisable sans jeton ni mot de passe SMTP ; `modules_actifs` : référentiel, serveur gagne.

## 7. Critères d'acceptation

- [ ] Désactiver `pisciculture` : entrée de menu retirée, URL directe `/elevage/poissons-chats` redirigée, aperçu au Dashboard Élevage, données intactes ; Goliaths/Pintades sans bascule interactive.
- [ ] Activer MeCeF sans IFU ou sans RCCM : refusé avec message ; IFU non numérique refusé.
- [ ] Compte créé depuis l'écran : peut ouvrir une session (preuve que l'écran n'est pas décoratif) ; le dernier admin ne s'archive pas ; `admin` non créable.
- [ ] Réinitialisation de mot de passe : sessions/jetons détruits, changement forcé, audit sans mot de passe.
- [ ] Restauration : un fichier renommé `.sqlite`, corrompu, d'un autre logiciel ou plus récent est refusé AVANT tout octet écrit ; la base précédente est conservée.
- [ ] Formulaire « Incubation et règles » : durée 0 ou 61 refusée avec le message du §4b ; jours de mirage « 14, 7 » refusés ; un animalier enregistre, un caissier est refusé ; un cycle déjà créé garde sa durée ; la modification arrive au poste (DV-11).
- [ ] Corbeille : « Archivé par » renseigné sur les 7 types ; AUCUNE écriture comptable n'y entre (DV-05) ; restauration d'un utilisateur par un non-admin refusée ; purge admin seule.
- [ ] Seuils de ferme : critique ≥ alerte refusé ; modification journalisée ; l'alerte d'autonomie suit le seuil modifié.
- [ ] Remise à zéro : sans mode « Données de Test » ou sans rôle admin → refus ; l'aperçu annonce les nombres réels ; les journaux d'audit restent.
- [ ] Logo : un `.exe` renommé en `.png` est refusé ; un fichier > 2 Mo refusé.
- [ ] Jeton e-MECeF et mot de passe SMTP absents de toute réponse `/api`, de tout journal et de toute table du poste.
